# Chunjae-Edu: KC 기반 오답 진단과 조언 파이프라인 (초안)

천재교육 중1-1 「정수와 유리수」 풀이 이력으로 **학생이 왜 틀렸는지**를 KC(지식 요소)와 오개념 단위로 진단하고, 정답을 알려주지 않고 스스로 고치게 하는 조언을 만든다. 상세 방법은 `DSL_수행방법론_KC파이프라인_v2.docx`(별도 배포)를 따른다.

> 상태 (2026-11-18): `데이터 전처리/`, `분석 데이터/`(조인 테이블), `사전/`(Eedi 기반 KC·오개념 사전, KC 묶음 초안)까지 완료. 나머지 스크립트는 할 일 주석이 달린 빈 파일이다.

## 1. 범위

| 구분 | 지식 |
|---|---|
| 1차 대상 (5개) | 유리수의 덧셈과 뺄셈의 혼합계산, 정수와 유리수의 대소 관계, 정수와 유리수의 덧셈, 정수와 유리수의 뺄셈, 정수와 유리수의 대소 관계의 활용 |
| **첫 실험 (2개)** | 유리수의 덧셈과 뺄셈의 혼합계산 (166문항, 풀이 4,105건), 정수와 유리수의 대소 관계 (138문항, 풀이 3,014건) |

## 2. 핵심 정의: Q행렬

**Q행렬 = 문항-선지마다, 그 선지를 고른 학생이 바르게 쓴 KC와 가졌을 오개념을 사전에서 골라 붙인 표.** 행은 문항-선지(정답 선지 포함, 단답형은 자주 나온 오답값), 열은 KC + 오개념이다. LLM(GPT·Claude)이 매핑한다. 세 버전은 값을 정하는 방식이 다르고, 버전마다 프롬프트가 따로 있다.

| 버전 | LLM에게 묻는 것 | 값 |
|---|---|---|
| 1 이진 | 후보 KC·오개념 중 맞는 것을 고른다 | 고른 것 1, 나머지 0 |
| 2 확률 | 추론한 뒤 후보 KC·오개념 각각에 점수를 매긴다 | KC는 점수 그대로, 오개념은 상위 10개 점수 |
| 3 세 값 | 후보 KC·오개념 각각을 판정한다 | 1 = 이 선지를 고르려면 있어야 함, 0 = 없어야 함, 빈칸 = 무관 (DiBello 외 2015) |

예: (-2/3)+(1/2)에서 정답 -1/6 선지는 KC {통분, 부호가 다른 수의 덧셈}. 오답 1/6 선지는 KC {통분} + 오개념 "절댓값이 큰 수의 부호를 따르지 않음". 버전3은 여기에 "부호가 다른 수의 덧셈 = 0"(할 줄 알았다면 이 오답을 피함)을 더 적는다.

공통 규칙
- 후보 KC는 그 문항에 배정된 KC(2단계 2), 후보 오개념은 그 KC에 연결된 오개념이다. 후보가 수십 개로 좁혀진다.
- 선지 하나에 KC는 최대 3개. 오답 선지의 KC는 같은 문항 정답 선지의 KC 안에서만 고르고, 코드가 검사한다(`kc_subset_ok`).
- LLM이 계산 경로를 먼저 쓰고, 코드가 재계산해 그 선지 값이 나오는지 기록한다(`trace_reproduced`).
- "해당 없음"(찍기·단순 실수·문제 오독)과 "신규 오개념 제안"을 허용한다.

## 3. 폴더와 실행 순서

번호가 실행 순서다. 모든 명령은 레포 루트에서 실행한다. 파일은 쓰임에 따라 두 형식이다.

| 형식 | 생김새 | 바꿀 곳 |
|---|---|---|
| **LLM 단계** (폴더) | `prompt.md` + `run.py` | `prompt.md`: 프롬프트(`## system`, `## user`, `## 원칙`, `## 예시`). `run.py` 맨 위 `CONFIG`: provider(openai/anthropic), model, prompt_stage, 실험 옵션, 그 아래 `OUTPUT_SCHEMA`: LLM 출력 형식 |
| **코드 단계** (파일) | `*.py` | 맨 위 `PARAMS`: 분석 설정. 그 아래 단계별 함수(할 일 주석) |

`CONFIG`·`PARAMS`의 값은 명령줄로 바꿀 수 있다. 예: `python "2단계 Q행렬/3_버전2_확률/run.py" --provider anthropic --kc-size group --prompt-stage 3`

세 Q 버전은 프롬프트와 LLM 출력 형식이 서로 다르다(고르기 / 후보별 점수 / 세 값 판정). 결과는 모두 같은 모양의 `Q.csv`(행 = 문항-선지, 열 = KC + 오개념)로 저장해 3단계에서 같은 지표로 비교한다. 결과는 각 단계 폴더의 `결과/<실행ID>/`에 생기고, 확정 Q행렬은 `3단계 검증/결과/확정/`에 둔다.

## 5. 실험 운영 규칙

1. 같은 단계 안의 방법은 **같은 입력, 같은 출력 형식**으로 만든다.
2. 실행 ID `<단계>-<방법>-<YYYYMMDD>-<순번>` (예: `2-v2-anthropic-original-p2-20261120-01`, `run.py`가 자동으로 만든다). 결과 폴더에 `config.json`, 결과 CSV, 메모를 두고 `실험 기록/실험_목록.csv`에 한 줄 남긴다(`data_io.new_run`, `finish_run`). Q 후보는 note 열에 q_id를 적는다.
3. 선정 기준은 결과를 보기 전에 `3단계 검증/선정_기준.md`에 적는다. 결과를 본 뒤 바꾸면 이유를 남긴다.
4. 세 Q 버전은 같은 선지 행·같은 후보에서 만들고 **같은 예측기·같은 분할·같은 지표**로 비교한다(`3단계 검증/선정_기준.md`).
5. **결과 CSV는 커밋한다.** LLM 원응답 캐시(`_cache/`)만 제외한다.
6. 학생 ID는 LLM에 보내지 않는다. API 키는 `.env`에만 둔다. 교재 원문 등 저작권 자료는 커밋하지 않는다.

## 6. 검토에서 정한 사항

| 항목 | 결정 |
|---|---|
| KCluster | **쓰지 않는다.** 유사도 계산에 문항 텍스트의 토큰 확률이 필요한데 GPT API는 생성 토큰 확률만, Claude API는 토큰 확률을 주지 않는다. 문항 하나에 KC 하나만 배정하는 한계도 있다. 팀이 만든 Eedi 기반 KC 사전을 쓰고 3단계에서 기준선과 비교해 검증한다 |
| KC 사전의 빈칸 | 대응 KC가 없던 곳에 새 KC `KC-N001~N007`(`status=active`)를 넣었고, 엑셀 밖 Eedi KC 2개(E297, E415)도 가져왔다. N006은 혼합계산 3번 토픽("~보다 ~만큼 큰/작은 수"), N007은 분수·소수 대소 비교이며 N002는 범위를 넓혔다. 혼합계산 5번 토픽(47문항)은 상황 읽기 세 유형으로 나눠 N001·N004·N005, 대소 관계 "나열된 수" 토픽(23문항)은 N002, 분수 계산(70문항)은 N003. 문항 유형 분류는 한 사람이 했으므로 팀 검토가 필요하다. 근거는 `1단계 사전/KC_확정_근거.md` |
| KC 크기 | Eedi KC는 형식 차이 수준까지 잘게 나뉘어 있다. 원래 KC(63개)와 묶은 KC(26묶음, `1단계 사전/3_build_kc_groups.py`의 초안 표) 두 버전으로 매핑해 비교한다 |
| Q행렬 열 | 세 버전 모두 KC + 오개념. 어느 버전을 확정해도 취약 KC와 오개념을 같은 Q행렬로 진단한다 |
| 버전3 세 값 | DiBello, Henson, Stout (2015, PMC5978573)의 선지 단위 세 값 코딩. 1과 0을 구분해 "필요한 지식"과 "피했어야 할 지식"을 함께 적는다 |
| 점수 | GPT는 토큰 확률, Claude는 확률 목록 또는 샘플링 비율. 의미가 달라 섞지 않는다 |
| Eedi 비중(%) | 오개념별 합이 100인 값이라 선지별 오개념 순위로 쓰지 않는다 |
| 챗봇 | 진단된 KC·오개념·학생 카드를 LLM 입력에 넣는다. 정답 전환율은 누설률과 함께 보고, 학습 효과는 다음 유사 문항 정답률로 본다 |
| 추가 데이터 1 (KT 확률) | 응답 기록은 기존 이력과 같고 완료일시가 손상됨. KT 확률은 안 푼 문항에만 있고 지식 안에서 1차원이라 KC·오개념 정보가 없다. 4단계 실력 지표로만 쓴다 |
| 추가 데이터 2 (T샘) | 학생·문항 ID가 기존 데이터와 하나도 겹치지 않고 문항 내용이 없다. 아래 보류 항목 |

## 8. 실행 환경

- Python 3.9 이상, `pandas`, `numpy`, `scikit-learn`, `openpyxl`, `python-dotenv`, `openai`, `anthropic`
- `.env.example`을 `.env`로 복사해 키와 모델을 채운다. GPT는 `OPENAI_*`, Claude는 `ANTHROPIC_*`(기본 모델 `claude-opus-5-5`, effort `high`, 거절 시 서버 측 대체 모델 재실행 `ANTHROPIC_FALLBACK=default`).
- 버전2의 GPT 토큰 확률 점수는 logprobs를 주는 비추론 모델이 필요하다(`OPENAI_SCORE_MODEL`). Claude는 토큰 확률을 주지 않아 후보 확률 목록(기본) 또는 샘플링 비율을 쓴다. 두 점수는 의미가 달라 섞지 않는다.
