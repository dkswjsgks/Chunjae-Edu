# 데이터 전처리

천재교육이 제공한 문항·학습자 풀이 이력을 **학생이 어디에서 왜 틀리는지 분석할 수 있는 형태**로 정리한 자료다. 팀원은 이 폴더의 전처리 결과를 바로 읽어 군집화, 문항별 오류 분석, 콘텐츠 매칭 실험을 진행할 수 있다.

**학생 오답 원인을 판정하거나 군집을 학습한 결과는 아니다.** 원문과 원본 채점을 보존하면서 분류·이미지·입력칸을 연결하고, 비교용 응답과 재채점 결과를 추가했다. 원문이 손상된 경우에는 추정으로 채우지 않고 검토 대상으로 남겼다.

기준일: 2026-11-01. 원본 CSV·문제 이미지는 기업이 별도로 제공한 자료이며 이 폴더에 새로 업로드하지 않았다. 전처리 결과에는 문항 내용과 난수화 학생 ID가 포함되어 있다. 원본 제공 범위 밖의 학생 전체 이력을 의미하지 않는다.

### 먼저 알아야 하는 용어

| 용어 | 뜻 |
|---|---|
| 지식 | 천재교육이 성취도를 평가하는 학습 단위. 예: 정수와 유리수의 뺄셈 |
| 토픽 | 지식을 구성하는 구체적인 학습 내용. 예: 정수의 뺄셈 |
| 학생·지식 조합 | 학생 한 명과 지식 하나의 묶음. 학생 A가 지식 3개를 풀었다면 요약표에 3행 생성 |
| 기준 정답 | 입력칸별로 비교할 허용 정답. 해설에 적힌 완성된 수식과 다를 수 있음 |
| 정규화 | 공백·전각·선행 + 등 표기 차이를 비교용 값에서 통일하는 작업 |
| 재채점 | 정규화한 응답과 기준 정답을 비교한 추가 결과. 원본 채점을 대체하는 공식 결과는 아님 |
| 미응답 | 모든 입력값이 비어 있거나 명확하게 모른다고 응답한 상태. 일부 칸만 비면 별도 구분 |
| 재풀이 | 같은 학생·문항이 현재 시험 완료일시보다 이전 이력에서 관측된 경우 |

## 2. 폴더 구성

```text
데이터 전처리/
├── readme.md                  이 안내서
├── 전처리 결과/               분석에 사용할 CSV·JSON과 변경·검토 기록
├── 코드/
│   ├── preprocess.py          전처리 재실행 코드
│   ├── manual_reviews.json    수작업 정답 순서·예외 처리·원문 수정 근거
│   └── test_preprocess.py     비교 규칙과 실제 산출물 검증
├── 분석 예제/
│   └── 학습요약_불러오기.py   결과 파일을 읽는 실행 예제

    └── readme.md              팀 실험·보고서 저장 안내
```

결과 파일명은 모두 한글이다. 기존 분석 코드와 연결할 수 있도록 기존 CSV의 열 이름은 유지했고, 새로 만든 학생별 지식 요약표의 열은 한글로 작성했다. 이전 영어 파일명과 현재 이름의 대응은 [전처리 파일_이름 안내.csv](<전처리 결과/전처리 파일_이름 안내.csv>)에 있다.

## 4. 원본에서 무엇을 어떻게 바꾸었는가

### 4.1 중2-2에서 밀린 열 1,908행 복원

일부 행은 학년·학기 값이 빠지고, 뒤의 값이 두 칸씩 왼쪽으로 들어가 있었다. CSV의 필드 수는 18개로 맞았으므로 열 개수만 검사해서는 발견할 수 없는 문제였다.

| 열 | 원본의 잘못된 값 예시 | 복원 후 |
|---|---|---|
| 문항 학년 | 8. 삼각형의 성질 | 2 |
| 문항 학기 | 2. 직각삼각형의 합동 | 2 |
| 대단원 | 소단원에 해당하는 값 | 8. 삼각형의 성질 |
| 중단원 | 토픽에 해당하는 값 | 2. 직각삼각형의 합동 |

문항번호로 문항 파일의 ‘2학년 2학기’를 확인하고, 뒤쪽의 문항형태·난이도·변별도 값과 빈 후미 두 칸을 대조해 복원했다. 복원 전후 값은 [데이터_복원 및 수정 이력.csv](<전처리 결과/데이터_복원 및 수정 이력.csv>)에 있다.

### 4.2 문항번호와 이미지 파일 연결

`40769390` 문항에는 `1학년 1학기 문제 이미지/40769390.png` 경로를 연결하는 방식으로 PNG 521장을 매핑했다. `image_sha256`에는 이미지 파일이 같은지 확인하는 해시를 저장했다.

이미지 파일 자체는 이 폴더에 새로 복사하지 않았다. 팀원이 별도로 받은 원본 폴더 아래에서 `image_path`를 찾아 사용한다. 제공 PNG에서 문제·정답·해설이 함께 있는 사례를 확인했으므로, 학생에게 문제로 보여줄 때는 정답 노출 여부를 먼저 확인해야 한다.

### 4.3 반복되는 분류 문자열을 ID와 분류표로 분리

풀이 행마다 학년·학기·대단원·중단원·소단원·토픽·지식 이름이 반복되어 있었다. 이름 대신 분류 항목을 구별하는 고유 ID를 사용하고, 이름과 부모 관계는 [단원 및 지식_분류표.csv](<전처리 결과/단원 및 지식_분류표.csv>)에 저장했다.

**같은 이름이어도 상위 단원이 다르면 다른 ID**가 된다. 학년 → 학기 → 대단원 → 중단원 → 소단원 → 토픽의 계층을 보존했다. 지식은 토픽 하나의 하위 단계로 만들지 않고, [토픽과 지식_연결표.csv](<전처리 결과/토픽과 지식_연결표.csv>)에서 연결했다.

교육과정 버전과 기업의 공식 분류 ID는 아직 제공되지 않아 별도 대체 ID를 만들었다. 새 교육학적 선행관계를 추정하거나 전체 지식 그래프를 구축한 것은 아니다.

### 4.4 완성된 정답을 입력칸 순서의 기준 정답으로 정리

해설 정답과 입력칸 값은 다를 수 있다. 예를 들어 전체 답이 `a=9/2, b=-2`이고 화면이 분자·분모·b를 따로 받는다면 입력값은 `[9, 2, -2]`가 된다. 이것은 형식을 설명하기 위한 예시다.

실제 문항 40770455의 전체 정답은 `-4/3`이지만, 음수 부호가 화면에 고정되어 있어 빈칸 기준 정답은 `["4", "3"]`이다. 첫 칸에 `-4`를 기대하면 잘못 채점하게 된다.

정답 처리된 원본 Y 응답을 정규화해 입력 순서를 참고했다. 서로 다른 Y 응답이 정규화 후에도 다르면 최빈값을 무조건 정답으로 삼지 않고 검토했다.

- 정답자 응답이 없는 단답 59문항은 원문·정답·관측 입력칸 수를 직접 대조했다.
- 55문항은 입력 순서를 정리했다.
- 원문이 손상된 4문항은 후보만 남기고 재채점을 보류했다.
- 단답 정답 추정 중 195문항은 원본 Y 응답이 단 1건이어서 추가 검토 표시를 했다.

입력칸별 허용 정답·근거는 [문항별 빈칸_기준정답.csv](<전처리 결과/문항별 빈칸_기준정답.csv>), 59문항 대조 결과는 [정답자 없는 59문항_검토.csv](<전처리 결과/정답자 없는 59문항_검토.csv>)에서 확인할 수 있다.

### 4.5 응답 표기를 비교용 값으로 통일

| 원문 응답 예시 | 정규화 값 |
|---|---|
| `+3`, `3.0`, `＋３`, `(+3)` | `3` |
| `- 14`, `−14` | `-14` |
| `덧셈의 교환 법칙`, `교환법칙` | `교환법칙` |
| `팔각형`, `8각형` | `8각형` |

영문 대소문자도 통일했다. 도형 이름을 답하는 문항에서는 선분 AB/BA와 각 ABC/CBA를 동치로 비교하되, 각의 가운데 꼭짓점과 RHA 등 합동 조건 명칭은 바꾸지 않았다. 임의의 식을 수학적으로 단순화한 것은 아니다.

`<`와 `≤`, `①`와 `1`처럼 의미가 다른 값은 합치지 않았다. 원문 응답은 `response_raw`, 비교용 값은 `response_normalized`로 나란히 보존했다. 정규화 이력은 [응답값_정규화 이력.csv](<전처리 결과/응답값_정규화 이력.csv>)에 있다.

### 4.6 여러 입력칸을 한 행씩 분리

원본의 `/^ROW^/`는 응답을 나누는 구분자다.

```text
원본: 9/^ROW^//^ROW^/-2

분리:
1번 입력칸 → 9
2번 입력칸 → 미응답
3번 입력칸 → -2
```

빈 토큰을 삭제하지 않아 입력 위치를 보존했다. 정답이 요구하는 칸보다 토큰이 부족하면 누락 칸을 별도 표시했다. 다만 단답형의 칸 수가 맞지 않고 응답이 남아 있으면 어느 칸이 생략됐는지 추정하지 않고 재채점을 보류한다.

객관식 복수선택에도 같은 구분자가 쓰였다. 이 경우 `blank_index`는 선택 토큰의 순서이며, 화면의 고정 빈칸이나 풀이 단계라는 뜻은 아니다.

### 4.7 빈칸 단위 비교와 문항 단위 재채점 추가

원본은 문항 전체의 Y/N만 제공했다. 각 입력값을 기준 정답과 비교해 맞은 칸·틀린 칸·미응답·판정 보류를 추가했다.

실제 문항 41020553에서는 `63/168=3/y`이므로 `y=8`인데, 원본 Y 응답 중 `63,4`가 있었다. 새 비교에서는 첫 칸 정답, 둘째 칸 오답으로 기록했다. **원본 Y는 그대로 보존**했다.

| 원본과 달라진 결과 | 건수 |
|---|---:|
| 원본 N → 비교 규칙상 전체 정답 | 34 |
| 원본 Y → 비교 규칙상 일부 정답 | 4 |
| 합계 | 38 |

대부분의 N→정답 차이는 표기·동치 처리에 따른 것이며, 원본 Y에서도 수학적으로 맞지 않는 값이나 복수선택 누락이 관찰됐다. 전체 목록은 [원본 채점과 재채점_불일치.csv](<전처리 결과/원본 채점과 재채점_불일치.csv>)에 있다. 기업의 채점 규칙을 확인하기 전에는 새 결과를 공식 채점으로 취급하지 않는다.

순서형은 위치대로, 단답 무순형·복수선택은 순서와 관계없이 중복 개수를 보존해 비교한다. 여러 허용 정답이 있으면 완전한 정답 배열 단위로 비교하고, 서로 다른 배열의 일부를 섞어 정답 처리하지 않는다.

### 4.8 미응답 상태 통일

| 원래 표현 | 건수 |
|---|---:|
| 응답 문자열 자체가 빈값 | 1,402 |
| 구분자만 있고 입력값은 모두 빈값 | 421 |
| ‘모름’ 등 명시적 표현 | 5 |
| 통합한 전체 미응답 | 1,828 |

일부 입력칸만 비어 있는 71건은 별도 상태로 남겼다. `?`, `...`, 임의의 문자는 실제 입력인지 무응답 표현인지 확정할 수 없어 일괄 미응답으로 바꾸지 않았다. 원본 채점 누락 8행은 현재 응답도 비어 있지만, 채점이 없다는 이유만으로 응답을 덮어쓰는 규칙은 만들지 않았다.

|---|---:|---|
| 해설 텍스트 없음 | 109문항 | 해설 이미지 설명·PNG 여부와 별도 표시 |
| 그림 자료 누락 후보 | 17문항 | 그림/그래프/수직선 언급 + 문제 이미지 설명·PNG 없음 |
| 문제에 `??` 존재 | 15문항 | 문자 손상 의심 표시 |
| 해설에 `??` 존재 | 41문항 | 문자 손상 의심 및 내용 검토 표시 |

그림 누락 후보에는 글만으로 풀 수 있는 문제도 포함될 수 있어 일괄 제거하지 않았다. `??`는 이미 원본 파일에 저장된 값이므로 재인코딩만으로 복구할 수 없다. 단일 `?`는 정상 물음표·생략 표현일 수도 있어 전부 손상으로 판정하지 않았다.

예외적으로 문항 40770383의 입력칸 사이 `=`는 제공 PNG에서 `>`임을 직접 확인해 복원했다. 이처럼 근거가 있는 수정만 했으며 원문·수정문·근거를 모두 남겼다. 알려진 수학적 모순도 기록했지만 전체 문항·해설의 수학적 정확성을 검수한 자료는 아니다.

### 4.10 재풀이 정보와 학생별 지식 요약 추가

동일 학생·문항이 이전 완료일시에 등장했는지 기록하고, 학생별 지식마다 풀이량·정답률·무응답·난이도별 관측량을 집계했다.

- 재풀이 1,297건을 구분해 새로운 문항 수행과 반복 노출을 따로 볼 수 있다.
- 같은 완료일시의 기록에 원본 행 순서로 임의의 선후관계를 만들지 않았다.
- 현재 자료에서 처음 관측됐다는 것이 전체 서비스에서 최초 풀이였다는 뜻은 아니다.
- 요약표 6,600행은 제공된 전체 기간의 현황이다. 특정 과거 날짜의 학생 상태로 사용하려면 이후 응답을 제외하고 다시 집계해야 한다.
- 비율에는 분모가 되는 풀이 수를 함께 제공한다. 분모가 0이면 빈값으로 두어 정답률 0과 구분한다.
- 난이도별로 관측 수·채점 수·정답 수·미응답 수를 함께 제공해, 풀지 않은 난이도를 오답으로 해석하지 않도록 했다.

## 5. 파일을 어떻게 연결하는가

| 연결 | 사용하는 열 |
|---|---|
| 풀이 이력 ↔ 문항 정보 | `item_id` |
| 풀이 이력 ↔ 빈칸 응답 | `attempt_id` |
| 풀이 이력 ↔ 지식명 | `knowledge_id` = 분류표의 `node_id` |
| 풀이 이력 ↔ 토픽명 | `topic_id` = 분류표의 `node_id` |
| 문항 정보 ↔ 입력칸 기준 정답 | `item_id` |
| 학생별 지식 요약 ↔ 개별 이력 | 요약의 `학생ID`, `지식ID` = 이력의 `student_id`, `knowledge_id` |

학생·시험·문항·분류 ID는 문자열로 읽는다. `attempt_id`는 현재 원본 파일의 레코드 순서로 만든 ID여서, 다른 원본 파일과 합칠 때는 입력 파일 해시 등을 함께 사용해야 한다.

CSV의 `response_normalized`, `analysis_cautions`, `expected_vectors`, `난이도별_관측통계` 등은 JSON 배열·객체를 문자열로 저장한 열이다. Python에서 `json.loads()`로 읽는다. `null`은 값 없음이고 숫자 0과 다르다. 비교용 숫자 응답도 정밀도 보존을 위해 문자열로 저장했다.

## 6. 채점·품질 관련 열을 읽는 방법

| 열 또는 값 | 뜻 |
|---|---|
| `source_correctness` | 원본 Y/N/빈값. 원본 기준 분석에 사용 |
| `regraded_result` | `correct` 전체 정답, `partial` 일부 정답, `incorrect` 맞은 입력 없음, `missing` 전체 미응답, `ungraded` 판정 보류 |
| `response_state` | 응답이 모두 있는지, 일부 비었는지, 전부 비었는지 |
| `analysis_cautions` | 채점 불일치·기준 정답 추가 검토·내용 검토·재풀이 등 해당 기록을 읽을 때 참고할 사항 |
| `answer_key_status=source_key` | 원본 객관식 정답으로 구성한 기준 |
| `answer_key_status=empirical_key` | 정규화 후 일치하는 원본 Y 응답들에서 추정한 기준. 독립적으로 검수한 공식 정답은 아님 |
| `answer_key_status=manual_key` | 수작업으로 원문과 입력 순서를 대조한 기준 |
| `answer_key_status=blocked_source_defect` | 원문 결함 때문에 재채점을 보류한 문항 |
| `answer_key_needs_review=1` | 확정 불가 또는 원본 정답 응답 1건만으로 기준을 추정한 경우 |
| `item_needs_content_review=1` | 도형 누락 후보, 손상 의심, 알려진 내용 모순, 해설 부족 등을 검토할 필요 |

주의사항이 있다고 무조건 삭제하는 것은 아니다. 분석 목적에 따라 포함·제외 조건을 정하고, 어떤 기준을 사용했는지 기록한다. 반대로 주의사항이 없다고 오답 원인이 확정된 것도 아니다.

## 7. 클러스터링을 시작할 때 확인할 점

군집화는 비슷한 응답 패턴을 묶는 작업이다. 이 자료에는 군집 라벨이나 확정된 오답 원인 코드가 없다.

1. **분석 단위를 정한다.** 학생 한 명 전체인지, 학생 한 명의 지식 하나인지에 따라 질문이 달라진다. 지식별 취약점을 보려면 학생·지식 요약에서 시작할 수 있다.
2. **원본 채점과 재채점 중 사용할 기준을 명시한다.** 둘을 설명 없이 섞지 않는다. 미응답·일부 정답·판정 보류도 구분한다.
3. **관측량을 함께 본다.** 1문항 중 1개 오답과 10문항 중 10개 오답은 증거량이 다르다. 임의의 최소 문항 수는 전처리에서 강제하지 않았다.
4. **서로 다른 문항에서의 반복을 확인한다.** 같은 문항을 여러 번 틀린 횟수와 다른 문항에서도 같은 기능을 틀리는 현상을 구분한다.
5. **선택지 번호 자체를 문항 간 공통 오류로 쓰지 않는다.** 서로 다른 문항의 ④는 같은 개념 오류를 뜻하지 않는다. 문항·선택지에 대한 오류 가설 검토가 필요하다.
6. **전체 정답률만으로 원인을 단정하지 않는다.** 난이도 구성·관측 토픽·무응답·재풀이 등과 함께 비교한다. 시험 점수는 같은 응답 결과를 포함하므로 정답률과 중복되거나 평가에 정답 정보를 섞을 수 있다.
7. **시간 데이터의 한계를 지킨다.** 있는 것은 시험 완료일시다. 문항별 반응속도·활성 풀이시간·실제 이동 순서·피로·포기 여부를 직접 계산할 수 없다.
8. **학습·평가에 미래 이력을 섞지 않는다.** 요약표와 문항 패킷의 응답 분포는 전체 제공 기간을 사용한다. 과거 시점 평가에서는 해당 시점 이전 자료로 다시 만들어야 한다. 학생·문항이 겹치는 이력을 무작위로 나누는 것도 목적에 맞게 검토한다.

KT 성취도·예측 확률은 원본에 없어 만들지 않았다. 군집 번호, 개념 결손, 단순 실수, 집중력 문제 등도 전처리에서 자동으로 부여하지 않았다.

## 8. 결과 파일 읽기와 검증

Python 3.10 이상이면 전처리·검증·예제 실행에 외부 패키지가 필요 없다. 아래 명령은 **레포 루트**에서 실행한다.

```bash
# 전처리 결과를 읽고 규모 확인
python "데이터 전처리/분석 예제/학습요약_불러오기.py"

# 비교 규칙과 결과 파일 검증
python -m unittest discover -s "데이터 전처리/코드" -p "test_*.py" -v
```

원본 자료 없이도 결과 데이터와 비교 규칙 검증은 가능하다. 원본 해시 검증 1개는 원본이 있을 때만 실행하며, 없으면 생략 사유를 표시한다. 다른 팀원이 별도 분석 라이브러리를 사용할 경우 해당 분석 폴더에 설치 방법과 버전을 기록한다.

게시 준비 시 원본 해시 검사를 포함한 24개 검증을 모두 통과했다. 원본으로 재실행한 데이터 파일 16개가 이 폴더의 사본과 바이트 단위로 일치하는 것도 확인했다. 설명서 안의 로컬 파일 링크와 불러오기 예제도 확인했다.

## 9. 원본으로 다시 전처리하기

원본 폴더는 아래 형태여야 한다.

```text
별도 제공받은 원본 폴더/
├── 문항_샘플.csv
├── 학습자 풀이 이력(아이디 난수화)_샘플.csv
└── 1학년 1학기 문제 이미지/
    ├── 40769390.png
    └── ...
```

```bash
python "데이터 전처리/코드/preprocess.py" --root "원본 폴더 경로"
```

기본 출력 위치는 이 레포의 `데이터 전처리/전처리 결과`다. 원본 폴더를 바꾸어도 출력 위치는 그대로다. 원본 CSV는 쓰지 않는다. 공통 결과를 덮어쓰지 않고 실험하려면 다른 폴더를 지정한다.

```bash
python "데이터 전처리/코드/preprocess.py" --root "원본 폴더 경로" --output "데이터 전처리/분석 결과/내 실험/전처리 결과"
```

원본 해시까지 검증하려면 다음처럼 원본 위치를 지정한다.

```powershell
# PowerShell
$env:CHUNJAE_RAW_ROOT = "C:/별도 제공받은 원본 폴더"
python -m unittest discover -s "데이터 전처리/코드" -p "test_*.py" -v
```

```bash
# macOS / Linux
CHUNJAE_RAW_ROOT="/별도 제공받은 원본 폴더" python -m unittest discover -s "데이터 전처리/코드" -p "test_*.py" -v
```

원본 문항 CSV는 CP949, 원본 풀이 이력은 UTF-8 BOM으로 읽는다. 전처리 CSV는 UTF-8 BOM, JSON·JSONL은 UTF-8이다. 모든 재채점 결과는 [manual_reviews.json](코드/manual_reviews.json)의 예외 판단과 비교 코드에 의존한다. 규칙을 바꾸면 코드·근거·검증·설명을 함께 갱신한다.

## 11. 팀 분석을 이어가는 방법

`분석 결과/` 아래에 실험별 폴더를 만들고 코드·노트북·군집 결과·보고서를 함께 저장할 수 있다. 사용한 커밋, 분석 대상, 포함·제외 조건, 특징 계산식과 분모, 원본/재채점 기준, 난수 시드와 실행 환경을 적으면 팀원이 비교하기 쉽다.
