# 천재교육 샘플 데이터 전처리 결과와 사용 방법

처리일: 2026-11-01

원본 CSV 두 개와 이미지 파일은 수정하지 않았다. 이 폴더의 CSV는 UTF-8 BOM 인코딩이고, JSON·JSONL은 UTF-8이다. JSONL은 한 줄에 문항 하나의 JSON 객체가 들어가는 형식이다. 전처리 코드는 `../코드/preprocess.py`, 수작업 판단 근거는 `../코드/manual_reviews.json`에 있다.

결과 파일명은 모두 한글로 바꿨다. 코드의 결과 저장 경로와 검증 코드도 함께 바꿔 재실행 시 영어 이름 파일이 다시 만들어지지 않도록 했다. 이전 이름과 현재 이름의 대응은 `전처리 파일_이름 안내.csv`에서 확인할 수 있다. 기존 열 이름은 팀원의 분석 코드와 연결할 수 있도록 유지했고, 새로 만든 학생별 지식 요약표는 열 이름도 한글로 작성했다.

### 이번에 추가한 분석 준비

| 추가한 정보 | 필요한 이유 | 확인할 파일 |
|---|---|---|
| 같은 문항의 이전 관측 수·재풀이 여부 | 동일 문항 반복 노출과 새로운 문항 수행을 구분하기 위해 | 학습자 풀이 이력_전처리.csv |
| 이전 지식 풀이 수·서로 다른 문항 수 | 해당 응답 이전에 어떤 이력이 있었는지 확인하기 위해 | 학습자 풀이 이력_전처리.csv |
| 채점·정답 근거·문항 내용의 주의사항 | 분류를 시작하기 전 불확실한 데이터를 찾기 쉽게 하기 위해 | 학습자 풀이 이력_전처리.csv |
| 학생별 지식 학습 요약 | 학생이 어느 지식에서 얼마나 풀고 틀렸는지 바로 파악하기 위해 | 학생별 지식_학습 요약.csv |

추가 정보로 학생의 개념 결손·집중력 저하·학습 성향을 자동 판정하지는 않았다. 재풀이 여부도 실제 화면 노출·풀이 시도 여부가 아니라 제공 로그에서 같은 학생·문항이 이전 완료일시에 관측됐다는 뜻이다.

| `normalization_데이터_복원 및 수정 이력.csv` | 비교용 응답 토큰의 표기가 달라진 기록 하나 | 정규화 전후 추적 |
| `전처리_검증 요약.json` | 전체 요약 | 건수와 원본 파일 해시를 자동 검사할 때 사용 |
| `학생별 지식_학습 요약.csv` | 학생 한 명의 지식 하나에 대한 전체 이력 요약 | 풀이량·정답률·미응답·난이도별 관측량 확인 |
| `전처리 파일_이름 안내.csv` | 파일 이름 대응 하나 | 과거 영어 이름으로 받은 파일과 현재 이름 연결 |

연결 방법은 다음과 같다.

1. `attempts.item_id = items.item_id`로 풀이와 문제를 연결한다.
2. `attempts.attempt_id = blank_responses.attempt_id`로 풀이와 입력칸을 연결한다.
3. `attempts.knowledge_id = ontology_nodes.node_id`로 지식명을 찾는다. 토픽명은 `topic_id`로 같은 방법을 쓴다.
4. 문항별 입력 정답은 `items.item_id = answer_keys.item_id`로 찾는다.

ID는 이름만으로 만들지 않고 부모 경로를 포함했다. 예를 들어 이름이 같은 토픽도 상위 단원이 다르면 다른 ID가 된다. 교육과정 버전은 아직 기업이 제공하지 않아 `unspecified`로 명시했다. 향후 공식 ID를 받으면 대응표를 만들어 교체해야 한다.

학년 → 학기 → 대단원 → 중단원 → 소단원 → 토픽은 부모·자식 계층이다. **지식은 토픽 하나의 하위 단계로 만들지 않았다.** 학기 아래 별도 평가 단위로 두고, `토픽과 지식_연결표.csv`에서 토픽과 연결했다. 이 파일은 원본 분류의 정규화 결과이며 별도의 교육학적 선행관계나 전체 지식 그래프를 구축한 것은 아니다.

## 4. 중요한 열과 값의 뜻

### 풀이 이력

- `attempt_id`: 이번 원본 파일의 논리적 레코드 순서로 만든 고유 풀이 ID. 원본 순서가 같으면 재실행해도 같다. 새로운 파일과 합칠 때는 파일 해시를 포함해 구분해야 한다.
- `source_record_number`: 원본의 헤더를 제외한 레코드 번호. CSV 안의 줄바꿈 때문에 텍스트 파일의 물리 줄번호와는 다르다.
- `source_correctness`: 기업 원본의 Y/N/빈값. 덮어쓰지 않았다.
- `response_raw`: 기업 원본 응답. 구분자와 공백까지 보존했다.
- `response_normalized`: 비교용 응답 배열. 숫자도 정밀도 손실을 막기 위해 문자열로 저장했다. 예: `["9","2","-2"]`. 빈 응답은 JSON `null`이다.
- `response_state`: `answered`는 모든 관측 토큰에 응답이 있음, `partial_missing`은 일부 토큰이 비어 있음, `missing`은 전부 비어 있거나 명시적으로 모른다고 응답함.
- `regraded_result`: `correct` 전체 정답, `partial` 일부 정답, `incorrect` 맞은 토큰 없음, `missing` 전체 미응답, `ungraded` 정답키·원문·입력 위치가 불확실해 판정 보류.
- `regraded_correctness`: 위 결과를 문항 단위로 표현한 Y/N. 미응답·보류는 빈값. 원본과 비교할 때만 보조로 사용한다.
- `test_completed_at`: 시험 완료일시다. 문항별 시작·제출·풀이시간으로 사용하지 않는다.
- `test_score_raw`: 원본 시험 점수. 같은 시험의 정답 결과를 포함하므로 문항 정오답 예측에서 무심코 사용하면 평가에 미래·정답 정보가 섞일 수 있다.
- `prior_item_attempt_count`: 같은 학생이 같은 문항을 현재 시험 완료일시보다 이전에 기록한 횟수.
- `is_repeat_item`: 위 횟수가 1 이상이면 1, 아니면 0. ‘다시 틀림’이나 ‘같은 오개념 반복’을 뜻하지 않는다.
- `is_first_observed_item`: 현재 자료 안에서 처음 관측된 학생·문항 기록이면 1. 같은 문항의 최초 기록이 같은 시각에 여럿이면 순서를 정할 수 없어 모두 0으로 둔다. 전체 서비스에서 최초 풀이였다는 뜻이 아니다.
- `same_time_item_attempt_count`: 같은 학생·문항이 현재와 정확히 같은 완료일시에 기록된 수. 이번 자료에는 2 이상인 경우가 없다.
- `prior_knowledge_attempt_count`: 같은 학생·지식에서 현재 완료일시보다 이전인 응답 수. 같은 시험의 다른 문항은 포함하지 않는다.
- `prior_knowledge_distinct_item_count`: 위 이전 이력에 포함된 서로 다른 문항 수.
- `answer_key_source`, `answer_key_status`: 빈칸 정답을 어디서 얻었고 어느 수준으로 확인했는지 표시. 정답자 응답을 이용한 추정과 원문 정답을 구분할 수 있다.
- `answer_key_needs_review`: 기준 정답을 확정하지 못했거나 정답자 1건에만 의존한 경우 1.
- `item_needs_content_review`: 도형 자료 누락 후보, 문제·해설의 `??`, 알려진 내용 모순, 사용할 해설 부족 등을 확인해야 하는 문항이면 1.
- `analysis_cautions`: ‘원본채점과_재채점_불일치’, ‘빈칸_기준정답_추가검토’, ‘동일문항_재풀이’ 등 해당 풀이를 해석할 때 참고할 사항의 배열. 배열이 비었다고 교육적 원인이 확정된 것은 아니며, 항목이 있다고 무조건 삭제하는 것도 아니다.

이전 이력은 시각을 정렬해 계산하되, 같은 완료일시에 있는 응답들을 한꺼번에 처리한다. 원본 행 순서·문항 순서·시험지 ID로 임의의 선후관계를 만들지 않는다. 원본은 시험 완료일시만 있으므로 실제 문항 풀이 순서나 소요시간은 알 수 없다.

### 학생별 지식 학습 요약

이 파일은 **제공된 전체 기간을 모은 현황표**다. 특정 과거 날짜의 학생 상태를 나타내는 표가 아니다. 과거 기준 평가에는 그 날짜 이후의 응답을 제외하고 다시 집계해야 한다.

| 열 | 의미와 계산 기준 |
|---|---|
| 학생ID·지식ID·지식명·학년·학기 | 누가 어떤 학습 단위에서 보인 기록인지 식별 |
| 총풀이수 / 서로다른_문항수 / 서로다른_시험수 | 반복해서 푼 횟수와 서로 다른 문제·시험의 수를 구분 |
| 관측_토픽수 | 제공 이력에서 실제로 관측한 토픽 수. 지식 전체의 토픽 수나 미학습 토픽 수가 아님 |
| 원본채점_있는수 / 원본채점_누락수 | 정답률의 분모와 누락 수를 확인 |
| 원본_정답률 | 원본 Y 수 ÷ 원본 Y 또는 N이 있는 수. 원본 N에는 무응답도 포함될 수 있음 |
| 첫관측_정답률 | 현재 자료에서 처음 관측된 학생·문항 기록 중 원본 Y/N이 있는 것만 계산. 최초 기록에 무응답이 있으면 다음 제출로 대체하지 않음 |
| 전체_미응답수 / 일부_미응답수 | 전부 비어 있는 응답과 일부 칸만 비어 있는 응답을 구분 |
| 원본오답중_응답있는수 | 원본 N 중 전체 미응답을 제외한 수. 구체적인 오답 값 분석에서 사용할 관측량 |
| 채점_불일치수 / 재채점_보류수 | 원본과 정규화 비교가 충돌하거나 비교를 보류한 수 |
| 문항내용_검토필요_문항수 / 기준정답_추가검토_문항수 | 불확실한 자료가 얼마나 포함되어 있는지 확인 |
| 난이도별_관측통계 | 난이도마다 관측 수·원본 채점 수·정답 수·미응답 수를 함께 저장. 풀지 않은 난이도를 오답으로 처리하지 않음 |

모든 비율은 0~1 값이며 분모가 0이면 빈값이다. 정답률이 0인 경우와 계산할 자료가 없는 경우를 구분한다. 표본이 적다는 이유만으로 유형을 부여하거나 임의의 성취 수준을 붙이지 않았다. KT 성취도나 정답 예측 확률도 새로 만들지 않았다.

### 입력칸 응답

- `blank_index`: 원래 응답을 분리한 입력 위치. 복수선택은 선택 토큰의 위치이지 화면의 고정 빈칸 위치가 아니다.
- `expected_token`: 순서가 있는 문항에서 비교한 정답값. 무순형·복수선택에는 위치별 유일한 정답이 없어 비워둔다.
- `matching_mode`: `ordered` 순서대로 비교, `unordered` 단답 무순형, `multi_select` 복수선택.
- `token_origin`: `observed` 원본에 있던 토큰, `padded_missing` 기대 입력 수보다 부족해 빈칸을 보완한 토큰.
- `grading_status`: 토큰별 정답·오답·미응답·판정 보류. 무순형의 정답은 ‘허용 집합에서 중복 사용 없이 매칭됨’을 뜻하며 특정 풀이 단계의 성공으로 해석하지 않는다.
- `positional_alignment_verified`: 원본 토큰 수가 기대 수와 일치하고 순서형 비교를 적용했는지 표시. 실제 웹 입력 폼을 직접 확인했다는 의미는 아니다. 관측 응답 기반 입력 구조이며 원본 폼이 있으면 추가 검증할 수 있다.

### 정답키: 입력칸별 허용 정답

- `source_key`: 원본 객관식 정답 기호로 만든 키.
- `empirical_key`: 정규화 후 일치하는 원본 Y 응답들에서 얻은 키. 교재와 독립 검증한 공식 정답은 아니다.
- `manual_key`: 수작업으로 원문과 입력 순서를 대조한 키.
- `blocked_source_defect`: 원문 결함 때문에 키를 확정하지 못함. 후보가 있어도 채점하지 않는다.
- `unresolved`: 풀이 이력이 없어 문항형태와 빈칸 순서 등을 확인하지 못함.
- `observed_correct_count`: 키 생성에 참고한 원본 Y 응답 수.
- `needs_key_review`: 확정 불가 또는 관측 정답이 단 1건인 추정 키. 추정 키 872개 중 단일 정답자만 있는 키는 195개다.

## 5. 적용한 비교 규칙과 한계

1. 전각 ASCII, 공백, 유니코드 마이너스, 선행 +, 숫자의 불필요한 소수 0, 숫자를 감싼 괄호, 영문 대소문자를 정규화했다. 문항 본문·해설 전체에는 이 응답 비교 규칙을 적용하지 않았다.
2. ‘덧셈의 교환법칙’과 ‘교환법칙’, ‘덧셈의 결합법칙’과 ‘결합법칙’을 통일했다. 다른 문장의 ‘덧셈의’는 삭제하지 않았다.
3. 팔각형/8각형 등 확인된 다각형 명칭, 문항 41020714의 ‘첫’/‘1’을 통일했다. 문항별 특수 동의어는 수작업 기록에 남겼다.
4. 도형 이름을 답하는 문항에서는 선분 AB/BA, 각 ABC/CBA를 동치로 비교했다. 각의 가운데 꼭짓점은 바꾸지 않았다. RHA·RHS 등 합동 조건 명칭은 뒤집지 않았다.
5. `<`와 `≤`, `①`와 `1`, 분수의 분자·분모는 합치지 않았다. NFKC 전체 변환으로 원문 번호나 위첨자를 훼손하지 않았다.
6. 분수의 `-`가 입력창 밖에 고정되어 있으면 빈칸에 음수를 다시 넣지 않았다. 예: 문항 40770455의 전체 정답은 -4/3이지만 입력키는 `["4","3"]`다.
7. 여러 정답 벡터가 가능하면 완전한 벡터 단위로 비교했다. 서로 다른 벡터의 일부를 섞어 정답 처리하지 않았다.
8. 무순형·복수선택에서는 제출된 값의 순서를 정답의 고정 위치로 해석하지 않았다. 같은 값을 두 번 제출해도 허용된 개수만 맞는 것으로 처리한다.
9. `?`, `...`, 임의의 문자 등은 명시적 무응답으로 확정할 수 없어 원래 응답으로 남겼다. ‘모름’ 등 명확한 표현만 공통 미응답으로 묶었다.
10. `??`는 손상 의심 표시다. 단일 ?는 정상 물음표나 생략 표현일 수 있어 전부 오류로 처리하지 않았다. 해설의 수학적 모순도 발견한 사례를 기록했으며 전체 해설의 수학적 정확성을 검증한 것은 아니다.

### 원본과 재채점이 다른 38건

- 원본 N → 비교 규칙상 전체 정답: 34건. +기호·공백·동치 표현, 허용된 덧셈 순서 등에 따른 차이.
- 원본 Y → 비교 규칙상 일부 정답: 4건. 아래 사례가 포함됨.
  - 41020553: `63/168=3/8`인데 학생 입력 `63,4`가 Y로 기록됨.
  - 40860216: 차가 3이고 곱이 40인 두 수에 `8,8`을 입력한 응답이 Y로 기록됨.
  - 41112282: 정답이 ①·⑤인 복수선택에서 ①만 제출한 응답 2건이 Y로 기록됨.

원본을 덮어쓰지 않고 별도 파일에 남겼다. 기업의 입력·채점 규칙을 확인하기 전까지는 ‘새 결과가 공식 정답’이라고 가정하지 않는다. 특히 원본 Y 응답에서 추정한 정답키가 많으므로 이를 그대로 진단 모델의 검증용 정답셋으로 사용하면 안 된다.

### 문항 패킷과 이미지 사용

`문항별 인공지능 분석_입력자료.jsonl`은 오프라인에서 문항을 분석·태깅하기 위한 입력이다. 정답·해설과 전 기간 오답 분포가 포함되어 있다. 학생에게 그대로 보여주거나 과거시점 예측의 입력으로 사용하지 않는다. 과거 기준 평가가 필요하면 해당 시점 이전 응답만으로 분포를 다시 만들어야 한다.

제공 PNG에서 문제·정답·해설이 한 이미지에 있는 사례를 직접 확인했다. 따라서 모든 PNG의 `image_contains_answer_or_solution=1`은 정답 노출을 막기 위한 보수적인 취급 표시다. 521장 모두를 시각 검수했다는 뜻이 아니다. 학생에게 문제 이미지를 제시하려면 정답·해설 영역을 분리하고 검토해야 한다.

## 6. 재실행과 검증

레포 루트에서 실행한다. Python 3.10 이상이 필요하며 전처리·검증에는 외부 패키지가 필요 없다. 원본 CSV와 이미지 폴더는 별도 제공받은 위치를 `--root`로 지정한다.

```powershell
python "데이터 전처리/코드/preprocess.py" --root "C:/별도 제공받은 원본 폴더"
python -m unittest discover -s "데이터 전처리/코드" -p "test_*.py" -v
```

기본 출력 위치는 `데이터 전처리/전처리 결과`다. 원본 입력 폴더를 바꾸어도 출력 위치는 그대로다. `--output`을 지정하면 다른 폴더로 저장한다. 검증 코드는 기본 출력 폴더를 읽는다.

원본 해시까지 검증하려면 PowerShell에서 `$env:CHUNJAE_RAW_ROOT = "C:/별도 제공받은 원본 폴더"`를 설정한다. 원본이 없으면 해당 검사 1개만 생략하고, 전처리 결과와 비교 규칙 검사는 실행한다. 원본이 없는 상황을 전체 검증 성공으로 혼동하지 않도록 생략 사유를 출력한다.

검증 내용: 원본 해시·행 수 보존, 1,908행 복원, PNG 521개 연결, 분류 관계의 연결·순환 여부, 각 응답을 분리한 뒤 원문으로 복원할 수 있는지, 무순형의 중복 개수, 복수선택 누락, 여러 정답 벡터의 부정확한 혼합 방지, 고정 음수 부호, 불확실한 정답 보류, 문항 패킷의 건수 일치와 학생 ID 미포함. 추가로 한글 파일명 생성, 재풀이 정보가 엄격히 과거 기록만 사용하는지, 같은 시각 기록에 순서를 만들지 않는지, 학생별 지식 요약의 분모·합계, 주의사항의 연결, 손상 의심 해설의 검토 표시를 검증한다.

원본 자료를 지정한 레포 패키지 검증은 원본 해시 검사를 포함해 24개다. 원본이 없으면 해당 검사 1개가 생략된다. 같은 원본으로 재실행한 결과 파일의 일치 여부도 확인했다.

소통 문서도 다시 읽었다. 10월 28일 협의의 우선순위인 ‘왜 틀렸는가’ 분석에 사용할 수 있도록 원문 응답·빈칸 위치·정답 추정 근거를 보존했다. 과거 소통에서 주관식 오답 저장 여부가 미확정이었지만, 현재 CSV에 실제 응답이 있으므로 그 관측 자료를 사용했다.
